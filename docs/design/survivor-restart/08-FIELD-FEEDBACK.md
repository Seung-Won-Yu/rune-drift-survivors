# 회복 기회·전투 피드백·부하 검사

2026-09-08. 캐릭터 단계 뒤 전장의 선택과 반응을 보강했다.

## 회복 열매

75초, 150초, 225초에 현재 위치에서 115 거리 떨어진 곳에 열매가 열린다. 각 열매는 체력 25를 회복하고, 80초 뒤 사라진다. 동시에 최대 3개만 존재한다. 공격이나 경험치 수집을 요구하는 별도 임무는 없다.

- 체력이 가득 차면 소모하지 않는다. 필요한 순간 직접 다가갈 수 있다.
- 경험치 자석의 영향을 받지 않는다. 접근 거리 25에서 수집한다.
- 체력 60% 미만이면 가장 가까운 열매의 방향을 알려준다. 화면 밖의 열매에는 회복 화살표가 나타난다.
- 열매는 파란 경험치와 다른 따뜻한 색, 잎과 십자 모양, `+25`로 구분한다.
- 회복량은 실제로 채운 체력만 집계한다. 열매·정예 처치·강화의 회복을 구분한다. 결과 상세에는 받은 피해와 회복한 체력을 표시한다.
- 공격으로 죽은 프레임에는 회복을 처리하지 않는다. 열매와 회복 효과의 시간도 일시정지와 함께 멈춘다.

회복 위치 계산은 전투의 난수 스트림을 소비하지 않는다. 출현 횟수/수명/효과/상한은 `field.js`에서 관리한다. 플레이의 위험을 상시 자동 회복으로 지우지 않고, 이동 경로에 선택을 추가하는 것이 목적이다.

## 움직임과 음향

처치한 적은 충돌에서 즉시 제외되고 0.26초 동안 짧게 눌리며 사라진다. 시각적 잔상은 최대 32개이며 보상·피해를 다시 발생시키지 않는다. 군주는 0.7초의 마무리 표현 뒤 결과 화면을 연다. 검사/불씨술사/수호자의 전용 공격·시전 그림과 검격/불씨/룬 효과는 유지한다.

검은 짧은 하강음, 불씨는 올라가는 발사음, 룬은 두 음의 울림으로 구분한다. 회복·강화·군주 격파에는 짧은 화음을 사용한다. 브라우저 AudioContext는 사용자 동작 후 시작하며, 음소거·일시정지·페이지 숨김에서 정지한다. 외부 음원 파일은 사용하지 않는다. 노드와 gain은 음이 끝나면 연결을 해제한다.

화면 흔들림을 새로 추가하지 않았다. `prefers-reduced-motion`에서는 피격 깜빡임과 선택적 눌림·기울임을 줄인다. 색 외에 공격 예고의 모양과 글자를 계속 제공한다. 짧은 가로 화면에서는 중앙의 일시 안내를 숨기고, 회복 안내를 왼쪽 여백으로 옮겨 캐릭터와 열매를 가리지 않는다. 방향 안내는 매번 읽어주는 live region으로 만들지 않았다.

## 검증과 수정

코어/캐릭터/프로필/전장 검사 41개, 브라우저 시나리오 30개를 사용한다. 41개 코어 검사가 통과했고, 브라우저는 전체 실행의 29개와 중단된 1개의 재실행이 통과했다. 변경한 안내 관련 3개도 재실행했다. 일반 Vite 빌드가 통과했다. 새 검사는 회복 출현/가득 찬 체력/실제 회복량/중복 수집/일시정지/수명/치명타 우선 처리/잔상 상한/사라짐/회복 중 효과 예산/소리 정지와 재개/3가지 화면의 회복 이동을 다룬다. 브라우저 검사 전체에 페이지 예외 수집을 적용했다.

초기 브라우저 검증에서 회복 타원의 Canvas 인자 누락으로 화면 갱신이 멈추는 오류를 발견해 수정했다. 회복 전후 상태와 실제 이동, 안내 종료를 재검증했다. 개발 중 HMR 갱신으로 모바일 부하 측정 하나가 중단된 경우는 기능 통과로 세지 않고, 코드 변경 종료 뒤 해당 검사와 회복 화면 검사를 재실행했다.

## 렌더링 부하의 범위

인위적인 부하 장면은 적 160개(군주 포함), 경험치 240개, 투사체 최대 80개, 세 진화 무기를 유지한다. 적의 체력은 부하가 빨리 사라지지 않도록 크게 설정했다. 이 값은 개발용 검사에만 사용한다. 각 화면에서 실제 requestAnimationFrame을 12초 동안 관찰하며, 군주의 공격과 일시정지 버튼까지 확인한다. 프레임 p95 50ms 미만을 회귀 기준으로 둔다.

이 데스크톱의 헤드리스 Chrome에서 1280×720과 740×360은 p95 약 16.7ms, 50ms 초과 프레임 0이었다. 390×844의 재측정도 p95 16.7ms, 50ms 초과 프레임 0이었다. [측정 JSON](./frame-timing-2026-09-08.json). 화면 크기만 모바일과 같게 한 검사이며 실제 휴대전화의 GPU·발열·배터리·터치 지연을 측정한 것은 아니다. 12초 부하 검사는 5분 실시간 통합 플레이를 대체하지 않는다.

캐릭터별 9회 전체 시뮬레이션도 재실행했다. 격파/생존 결과와 시간은 캐릭터 단계의 최종 로그와 같고, 일부 경로가 이동 중 열매를 얻어 잔여 체력이 달라졌다. 봇에게 열매로 이동하는 새 특혜 경로는 추가하지 않았다. [전장 추가 후 로그](./balance-field-2026-09-08.jsonl).

화면 증거: `output/playwright/survivor/recovery-*.png`, `stress-*.png`. 프레임 JSON은 Playwright 첨부 자료와 QA 로그에 생성된다. 다음 단계는 코드 정리, 전체 런의 브라우저 통합, 기존 게임 회귀, Pages 배포와 최종 전달이다.
