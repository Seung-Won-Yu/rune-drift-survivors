# 결과에서 다음 빌드로 이어지는 실험

2026-10-06 · 첫 챕터의 재도전 연결 개선.

## 문제와 의도

기존 결과는 처치·생존·피해 기여와 누적 발견 수를 보여줬지만 이번 판에 처음 발견한 선택이 무엇인지 드러내지 않았다. 다음 목표도 모든 동료의 해금/발견을 순서대로 제시해, 방금 사용한 시작 무기를 다른 방식으로 시험하는 행동과 거리가 있었다.

새 결과는 실제 첫 발견을 표시하고 같은 동료의 다른 전문화를 다음 판 목표로 준비하게 한다. 목표는 선택을 기억하는 안내다. 출발 능력이나 강화 후보, 획득 조건을 바꾸지 않는다.

## 동작

- 기록 가능한 종료 판에서 새 전문화·진화·유물을 기존 발견과 대조한다. 쓰러진 판도 발견을 기록한다. 중복 결과와 기록 ID가 없는 개발 장면은 새 발견을 만들지 않는다.
- 결과의 ‘다음 판의 실험’은 해당 동료의 시작 무기 중 이번 판에 선택하지 않은 전문화를 제안한다. 미발견 갈래를 우선하고, 모두 발견했다면 다른 갈래를 제안한다.
- ‘이 빌드로 다음 판 준비’는 동료 선택 화면으로 이동한다. 목표와 효과, 무기 3단계·레벨 4 조건을 확인한 뒤 직접 출발한다.
- 목표를 브라우저에 저장한다. 기존 v1 기록은 유지하며 목표가 없는 예전 기록은 그대로 불러온다. 다른 시작 무기나 알려지지 않은 목표는 제거한다.
- 실제 성장 후보에 목표가 등장하면 ‘이번 판의 목표’ 표시를 붙인다. 다른 후보도 선택할 수 있다. 일시정지/결과에서는 준비·선택 완료·방향 변경 상태를 표시한다.
- 목표 삭제와 다른 동료 선택은 목표를 지운다. 기념품 변경은 목표를 유지한다. 새 판의 전문화·진화·유물은 획득하기 전 상태로 돌아간다.
- 저장 실패 시 메모리에서는 계속 사용할 수 있고 기존 저장 경고가 남는다. 새 발견은 해당 결과 화면을 다시 구성하더라도 유지한다.

## 조사에서 가져온 판단

[의미 있는 선택 조사](./references/meaningful-run-choices.md)의 자율성·숙련 피드백 원칙을 이 흐름에 적용했다. 처음 발견한 행동을 구체적으로 되돌려주고, 다른 전문화를 직접 선택하도록 돕는 것은 해당 연구를 바탕으로 한 설계 해석이다. 재도전율이나 재미가 향상됐다는 관찰 결과는 아직 없다.

추가 영구 능력치, 연속 접속 보상, 출발 전 상점을 넣는 대신 현재 6개 전문화의 차이를 반복해서 경험하도록 연결했다. ‘이 빌드’는 전문화 방향이며 직전 판의 힘을 복사한다는 뜻이 아니다.

## 검증

- 새 단위 검사 7개: 첫 발견·중복·미종료 판, 이전 저장 형식, 잘못된 목표, 저장/삭제, 동료별 추천, 정상 전투/성장 후보 동일성, 완료/방향 변경.
- 새 브라우저 검사 8개: 1280×720·320×740·740×360 결과→준비→새로고침→출발→실제 선택→재도전, 키보드 준비, 다른 갈래, 삭제, 동료 변경, 기념품, 저장 실패, 새 발견 중복 방지.
- 전체 회귀 검사: 단위 98개, 브라우저 81개 통과(약 3.5분). Pages용 빌드와 production 시작·일시정지·PNG 5개·개발 전역 제거 검사 통과.
- 실제 시간 전체 플레이 3판 통과, 종료 코드 0: 검사/불씨술사 군주 격파, 수호자 300초 생존. 두 사건·저장·재시작·다음 실험 표시를 확인했다. [전체 기록](./chapter-fullrun-2026-10-06.json).

그림 검수는 결과의 다음 실험, 320px 목표 준비, 320px 실제 성장 후보에서 수행했다. 물리 휴대폰 사용감과 사람의 재도전 의사는 자동 검사로 대신하지 않는다.

기존 보상 개선의 18경로 진단과 전투 결과 JSON이 그대로 일치한다. [최신 로컬 QA](./experiments-local-qa-2026-10-06.json), [전체 제작 기준 대조](./20-CHAPTER-FINAL-AUDIT.md).

인앱 브라우저 일반 실행에서도 검을 3단계까지 키우고 레벨 4에서 반월 검법을 실제로 골랐다. 1분 15초의 쓰러짐 결과에 ‘새 발견 · 반월 검법’이 표시됐고, 다음 일점 검법 실험을 눌러 동료 선택의 목표 준비 화면으로 이동하는 것을 확인했다. 이 실행은 DEV 장면을 사용하지 않았다.

목표 준비 직후에는 출발 버튼까지 보이도록 화면을 이동한다. 기존 준비 화면 전체를 스크롤할 수 있으며, 1280px·320px·740px에서 출발 버튼이 화면에 들어오는 조건을 추가해 관련 8개 검사를 다시 통과했다.

## main과 공개 전달

실행 커밋 `26368303f08d86838deadcbb46cdb3e217f80e82`를 main에 푸시했다. [원격 실행 37406528238](https://github.com/Seung-Won-Yu/rune-drift-survivors/actions/runs/37406528238)의 build/deploy가 모두 성공했다. 코어 98개·새 게임 화면 81개·기존 3D 회귀 86개와 Pages용 실행 검사 통과를 실제 로그에서 확인했다. [원격 검사 기록](./chapter-release-ci-2026-10-06.json).

공개 HTML이 검수한 빌드의 JS/CSS를 참조하며 세 파일의 SHA-256이 일치한다. 공개판 PNG 5개·시작·정지·QA 전역 제거 검사에 HTTP/페이지 오류가 없었다. [공개 파일과 실행 기록](./public-chapter-2026-10-06.json).

인앱 공개 페이지에서도 DEV 장면 없이 황동 검 3단계와 레벨 4에 도달해 반월 검법을 골랐다. 1분 5초·84처치의 쓰러짐 결과에서 첫 발견과 다음 일점 검법 실험을 확인했다. 준비→새로고침 후 목표·기록 1회·불씨술사 해금이 유지됐고, 새 판은 레벨 1·0처치·검 1/3단계·전문화 미획득·유물 0/2로 시작했다. 이는 일반 UI 동작 검수이며 사람의 재미 평가로 사용하지 않는다.
