# 첫 챕터 통합과 전달 기록

2026-09-08. `00-RELEASE-PLAN.md`의 범위인 2D 카툰 서바이버 첫 챕터를 기준으로 통합한다. 기존 3D 게임은 루트에 보존하고 새 게임은 `/survivor/`로 제공한다.

## 실제 시간의 전체 플레이

고정된 소스 복사본의 별도 Vite 서버에서 세 독립 헤드리스 Chrome을 실행했다. 일반 생성 상태와 시드 42로 시작하고 이동·강화 선택만 입력한다. 체력·피해·난이도·시간 배율은 바꾸지 않는다. 자동 입력 코드는 DEV 전용 동적 import로 연결하며 배포본에는 QA 전역과 입력 코드가 포함되지 않는다.

| 동료 / 화면 | 게임 시간 | 결과 | 처치 / 레벨 | 실제 경과 | 프레임 p95 |
| --- | --- | --- | --- | --- | --- |
| 검사 / 1280×720 | 293.88초 | 군주 격파 | 954 / 20 | 294.86초 | 16.7ms |
| 불씨술사 / 390×844 | 278.88초 | 군주 격파 | 949 / 20 | 279.87초 | 16.7ms |
| 수호자 / 740×360 | 300초 | 생존, 군주 남음 | 959 / 20 | 300.71초 | 16.7ms |

각 판은 정예 3마리와 해당 무기 진화를 거쳤다. 50ms 초과 프레임과 페이지 예외는 세 실행 모두 0이었다. 결과에서 기록이 한 번 저장됐는지, 재도전에서 처치/시간을 초기화하고 같은 동료로 시작하는지 확인했다. 수호자의 생존은 격파로 기록하지 않는다. 자동 입력의 결과는 사람의 승률이나 재미 평가를 의미하지 않는다. [전체 수치](./fullrun-2026-09-08.json).

재현: 개발 서버 실행 후 `npm run qa:survivor:fullrun`. 서버를 따로 고정한 경우 `ASH_FULLRUN_URL=http://127.0.0.1:5175 npm run qa:survivor:fullrun`. 실행 중 해당 서버 소스를 수정하면 HMR이 검사 페이지를 바꾸므로 수정하지 않는다.

## 코드와 검증 경계

- `game.js`: 순수 전투/성장/개체 상한. UI나 저장소와 독립적이다.
- `boss.js`, `field.js`: 군주 공격, 제한된 회복 기회와 실제 회복량.
- `characters.js`, `profile.js`: 동료 정의/해금, 버전이 있는 로컬 기록 정규화와 저장 실패 처리.
- `render.js`, `audio.js`: Canvas2D 표현과 짧은 WebAudio 효과. Three/React를 새 게임 런타임에 끌어오지 않는다.
- `camp.js`, `main.js`, `style.css`: 대기/결과 표시, 상태 전환/입력/고정 시간 루프, 반응형 화면.
- `qa-pilot.js`: DEV 전용 정상 입력 자동화. 결과 저장은 일반 경로를 사용한다.

긴 한 줄 JS/CSS를 정리했다. JS는 파싱한 AST를 비교하고, CSS는 원문/위치 메타데이터를 제외한 파싱 구조를 비교해 포맷 정리의 의미가 동일함을 확인했다. 600px 높이의 데스크톱에서도 대기 화면 위쪽이 잘리지 않도록 안전한 중앙 정렬과 스크롤 검사를 추가했다. 예전 비교 시트는 스타일 실험실 자료로만 남겨 런타임에서 읽지 않는다.

배포 workflow는 기존 게임 QA, 새 게임 코어/브라우저 QA, Pages 하위 경로의 실제 빌드 QA를 모두 통과한 뒤 artifact를 배포한다. `GITHUB_PAGES=true npm run build` 다음 `npm run qa:survivor:production`을 실행하면 임시 preview를 자체 실행/정리하며 배포본의 이미지·시작·일시정지와 QA 전역 부재를 검사한다.

## 남기는 한계

- PC Chrome과 모바일 화면 크기/터치 에뮬레이션에서 확인했다. 실제 저사양 휴대전화의 장시간 발열·배터리, iOS Safari 기기 검증은 수행하지 않았다.
- 그림은 생성된 4포즈 애니메이션이며 좌우 반전을 쓴다. 일부 공격 셀 끝의 작은 잘림과 포즈 간 비율 차이는 자산 문서에 기록했다. 이는 전용 다방향 수작업 애니메이션을 완료했다는 의미가 아니다.
- 런타임 PNG 5개의 합계는 약 7MB이다. 재도전에는 다시 로드하지 않지만 최초 연결이 느리면 준비 시간이 필요하다. 실패 시 재시도가 가능하다.
- 로컬 기록은 현재 브라우저/출처에 저장한다. 클라우드 동기화, 상점, 계정, 온라인 대전은 이 챕터 범위에 없다.

## 최종 로컬 게이트

- 기존 3D 게임: 84개 전체 브라우저 검사 통과.
- 새 게임: 코어 41개 통과. 브라우저 32개 중 전체 실행의 31개와 스크롤 가장자리의 0.05px 반올림 허용 후 재실행한 1개 통과.
- 최대 부하: 세 화면에서 p95 약 16.7~16.8ms, 50ms 초과 0. 전체 실행과 별도의 재현 로그는 각 시점 문서에 남아 있다.
- 중첩/흑백 검수: 모션 감소 상태의 390×844 최대 부하 장면을 확인했다. 밝은 머리의 플레이어, 낮은 사냥개, 작은 버섯, 넓은 나무 거인, 큰 왕관의 군주가 실루엣으로 구분된다. 160개 적과 피해 숫자가 겹치는 최악의 장면에는 시각적 혼잡이 남는다.
- Pages base 빌드와 자체 preview 검사 통과. 5개 그림 로드, 시작·일시정지, 개발용 전역/자동 입력 코드 미포함을 확인했다.
- README를 현재 3명/3진화/보스/회복/기록의 최종 기능으로 다시 작성하고, 새 게임 안내와 실제 화면을 갱신했다. 설계 문서의 로컬 링크 검사에서 누락 없음.
