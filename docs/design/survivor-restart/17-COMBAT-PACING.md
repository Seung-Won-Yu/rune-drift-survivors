# 5분 전투의 공세와 정리 시간

작성: 2026-10-06

## 목적

기존에는 시간이 지날수록 일반 적의 증원이 계속 빨라졌다. 강화해도 압박이 비슷하게 유지되는 문제를 줄이기 위해, 기존 5분 안에서 공세와 정리 시간을 번갈아 배치한다. 이번 범위는 전투 리듬이며 새 콘텐츠나 재도전 보상은 추가하지 않는다.

## 구현

`src/survivor/pacing.js`가 게임 시간 기준으로 일반 적의 증원 간격과 HUD 안내를 함께 결정한다. 기존 시간별 증원 간격에 아래 배율을 적용한다. 배율 0.55는 기존 속도의 55%로 증원한다는 뜻이다. 적의 체력·접촉 피해·경험치 값·이동 속도는 바꾸지 않는다.

| 경과 시간 | 흐름 | 증원 속도 배율 |
| --- | --- | --- |
| 0–40초 | 첫 무기 익히기 | 1.00 |
| 40–60초 | 첫 공세 | 1.20 |
| 60–78초 | 정예 대응 | 1.00 |
| 78–92초 | 정리·수집 | 0.55 |
| 92–110초 | 재집결 | 0.95 |
| 110–130초 | 두 번째 공세 | 1.10 |
| 130–145초 | 정리·수집 | 0.55 |
| 145–170초 | 재집결 | 1.00 |
| 170–192초 | 후반 공세 | 1.00 |
| 192–207초 | 정리·수집 | 0.55 |
| 207–230초 | 마지막 공세 | 1.00 |
| 230–240초 | 보스 전 정리 | 0.45 |
| 240초 이후 | 보스전 | 기존 1.6초당 1마리 |

- 무기 진화를 실제로 선택하면 게임 시간 8초 동안 일반 증원을 45%로 낮춘다. 기존 적을 지우거나 체력을 깎지 않으므로 새 무기로 직접 처치한다.
- 같은 시각의 연속 진화는 시간을 누적하지 않는다. 일반 강화에는 적용하지 않는다.
- 정예 등장과 보스의 240초 등장은 미루지 않는다. 진화의 여세도 보스 등장 시 끝난다.
- 남아 있는 적과 공격은 계속 위험하다. `숨 고르기`는 안전·무적 상태가 아니다.
- 기존 타이머 위에 `밀려오는 무리`, `숨 고르기`, `진화의 여세`와 남은 초를 표시한다. 별도 패널이나 화면 흔들림을 추가하지 않는다.
- 일시정지·강화·유물·상자 선택 중에는 게임 시간이 멈추므로 해당 시간도 소모하지 않는다.

## 비교 진단

`scripts/survivor-pacing-balance.mjs`로 6개 빌드 경로 × 시드 12/42/99, 총 18판을 변경 전후 동일한 자동 입력으로 실행했다. 실제 적·체력·선택 규칙을 사용하며, 체력 보정이나 강제 승리는 없다. [전체 기록](./pacing-balance-2026-10-06.json)에 30초별 상태와 진화 시점을 남겼다.

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 군주 격파 / 생존 / 패배 | 12 / 4 / 2 | 13 / 4 / 1 |
| 평균 최종 레벨 | 19.9 | 18.9 |
| 평균 처치 수 | 951.4 | 809.4 |
| 첫 진화 시점 범위 | 70.6–97.5초 | 74.3–97.4초 |
| 관측 최대 동시 적 | 101 | 111 |

첫 시도에서는 후반 공세까지 증원을 늘려 일부 불씨 경로가 193–204초에 패배했다. 후반은 기존 증원 속도를 상한으로 삼았다. 최종 진단에도 불씨 확산 경로 한 판은 230초에 패배했으며, 자동 조작에 맞춰 승리를 보장하도록 조정하지 않았다.

이 수치는 사람의 승률이나 재미 평가가 아니다. 처치·경험치 총량이 감소해 최종 레벨이 평균 약 1 낮아지는 변화가 있다. 모든 진단 경로에서 진화는 유지됐다. 밀집도는 기존 적과 동선에 따라 잠시 높아질 수 있으므로 `휴식 즉시 화면이 비워짐`을 보장하지 않는다.

## 확인과 후속 기준

- 단위 검사: 모든 시간 경계, 실제 증원 감소, 기존 적/경험치 보존, 세 진화, 연속 진화, 일반 강화 제외, 정지·재시작, 정예·보스 시점.
- 브라우저 검사: 기존 플레이 회귀, 실제 진화 선택 후 HUD, 1280×720 / 320×740 / 740×360에서 안내·정지·보스 전환.
- 실제 사람에게 확인할 것: 강화 후 힘이 느껴지는지, 수집·이벤트로 방향을 바꿀 여유가 생기는지, 보스 직전이 지루하지 않은지. 그 반응을 보고 시간과 증원 배율을 다시 조정한다.
- 실제 휴대폰 성능과 자발적인 재도전 여부는 이번 자동 진단으로 검증하지 않았다.

## 로컬 검증 결과

2026-10-06: 단위 검사 87개, 브라우저 시나리오 70개 통과. Pages용 프로덕션 빌드와 해당 경로의 시작·일시정지·이미지 로딩·QA 전역 제거 확인 통과. 변경 전후 18판씩 진단을 완료했다. 최대 부하 렌더 검사 p95는 1280/390/740px에서 각각 16.8/16.8/16.7ms, 50ms 초과 프레임은 모두 0이었다. 데스크톱 브라우저 측정이므로 실기기 성능을 뜻하지 않는다.

인앱 브라우저의 일반 플레이에서 검 강화와 첫 공세 안내를 확인했다. [320px 정리 시간](./images/pacing-rest-320.png), [1280px 공세](./images/pacing-surge-1280.png)는 자동 브라우저 시나리오 캡처다.

실시간 브라우저 전체 실행도 세 캐릭터에서 완료했다. 시드 42의 일반 입력 자동화로 검사 289.9초 군주 격파, 불씨술사 288.8초 군주 격파, 룬 수호자 300초 생존. 모두 두 이벤트, 진화, 정예 3회, 결과 저장과 재시작 확인을 통과했고 런타임 오류는 없었다. [실시간 기록](./pacing-fullrun-2026-10-06.json). 세 브라우저를 동시에 실행한 측정에서 p95는 16.7–16.8ms였으며, 50ms 초과 프레임은 검사 8회, 나머지는 0회였다.

구현 커밋 `be1e56e`를 main에 푸시했다. [Pages 배포 실행](https://github.com/Seung-Won-Yu/rune-drift-survivors/actions/runs/37398077187)은 새 게임 QA와 프로덕션 확인을 통과했고, 이 기록 시점에는 기존 3D 게임 회귀 검사가 진행 중이다. 공개 페이지에 새 버전이 반영됐다는 확인은 아직 하지 않았다.

전체 실행 스크립트는 모든 assertion 후 요약 파일을 저장했지만 Node 프로세스가 연결 핸들을 유지해 자동 종료되지 않았다. 결과 저장을 확인한 뒤 해당 검사 프로세스만 종료했다. 따라서 전체 실행은 플레이 assertion 완료로 기록하며 정상 exit-code 통과로 계산하지 않는다.
