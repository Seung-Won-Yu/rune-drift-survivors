## 이번 보강의 결과

공세와 정리 시간을 번갈아 배치하고 진화 직후 잠시 증원을 줄였다. 사건의 실제 보상 후보를 미리 보여주고 무기/유물 연결을 설명한다. 결과는 이번 판의 새 발견을 드러내며, 같은 동료의 다른 전문화를 다음 판 목표로 준비할 수 있다.

이 세 변경은 기존 전투·위험·성장을 경험하고 다른 선택으로 재도전하는 흐름을 보강한다. 지도·무기 수를 추가하는 것은 이번 마감의 필수 조건으로 잡지 않았다.

## 최신 로컬 검증

- 단위 검사 **98개**, 브라우저 시나리오 **81개** 통과. 새 재도전 기능의 7개 단위·8개 화면 검사 포함.
- 최대 부하 세 화면의 p95 **16.7~16.8ms**, 50ms 초과 프레임 **0**. 이번 로컬 Chrome의 측정값이다.
- 변경 전후 정상 입력 18경로의 JSON 결과가 일치한다. 결과는 [보상 선택 진단](./choices-balance-2026-10-06.jsonl)과 동일하며 사람의 승률이나 재미를 나타내지 않는다.
- Pages용 production 빌드와 하위 경로 검사 통과: PNG 5개, 시작/정지, HTTP/페이지 예외 없음, QA 전역 제거.
- 인앱 일반 UI에서도 반월 검법 획득→쓰러짐→첫 발견→일점 검법 목표 준비를 확인했다.
- 결과→다음 실험 준비→새로고침→출발→실제 선택→재도전, 다른 갈래 선택, 목표 삭제, 동료 변경, 기념품 변경, 저장 실패 검사 통과.
- [최신 QA 수치](./experiments-local-qa-2026-10-06.json), [재도전 화면과 설계](./19-REPLAY-EXPERIMENTS.md), [공세 리듬](./17-COMBAT-PACING.md), [선택 조사](./references/meaningful-run-choices.md).

전체 시간 검사는 수동으로 브라우저를 띄우던 Node 스크립트에서 Playwright의 독립 fixture/worker 관리로 옮기고 설치된 Chromium을 사용한다. 게임 규칙을 완화하지 않았으며 전체 플레이·두 사건·저장·재시작의 기존 조건과 결과의 다음 실험 표시를 검사한다. 세 실행이 모두 성공하고 프로세스가 정상 종료해야 summary를 작성한다.

## 실제 시간 전체 플레이

## 남은 평가의 경계

사람이 느끼는 재미·스릴·재도전 의사는 아직 자동 검사로 확인할 수 없다. 실제 저사양 휴대전화의 발열/메모리/배터리와 iOS Safari 검증은 별도다. PNG 원본 약 7MB와 생성 시트의 4포즈·좌우 반전·일부 프레임 잘림은 [자산 문서](../../../public/art/survivor/README.md)와 [기존 출시 기록](./09-RELEASE.md)에 남아 있다.

한 판의 전투와 재도전 연결을 구현했다고 장기 리텐션이나 상업용 애니메이션 품질을 검증한 것으로 보지 않는다. 다음 기획 확장은 실제 플레이 관찰에서 ‘언제 피격 원인을 놓치는가’, ‘왜 특정 갈래를 고르는가’, ‘다른 빌드를 다시 해보고 싶은가’를 확인한 뒤 정한다.

## 최종 검수 추가 대조

2026-10-06에 mobile-game-qa 기준으로 현재 소스와 실제 검사 조건을 대조했다. 모바일 HUD 버튼은 44×44px이며 safe-area 여백과 터치 취소를 처리한다. 최초 로딩/그림 실패의 재시도, 일시정지/음소거, 선택 화면의 초점 순환과 숫자키, 모션 감소의 위험 표시가 현재 검사에 포함된다.

최신 코어/브라우저 로그, 세 전체 플레이 JSON과 실행기의 정상 종료, 제작/조사 문서 24개의 로컬 링크를 확인했다. 개발 안내에 남아 있던 이전 검사 수치 82/67을 현재 98/81과 전체 플레이 3개로 고쳤다. 현재 흑백 최대 부하 화면, 피격 화면, 320px 목표 선택 화면을 직접 검수했다. 최대 160개 적을 영구 생존시키는 개발 부하 장면에서는 실루엣이 겹쳐 혼잡하다. 이 검사를 정상 플레이의 가독성이나 사람의 재미 증거로 사용하지 않는다. 이는 기존에 명시한 시각적 혼잡 한계이며 추가 콘텐츠로 감추지 않는다.
