# 보상을 알고 선택하는 숲의 사건

2026-10-06

## 결정

첫 챕터의 다음 개선은 위험 대비 보상을 이해하는 선택이다. 기존 제단·상자는 완료할 때 유물을 무작위로 뽑아 보여주므로, 접근하거나 저주를 수락할 때 내 빌드에 무엇을 얻을지 판단하기 어려웠다. [조사 기록](./references/meaningful-run-choices.md)을 바탕으로 후보를 미리 정하고 현재 빌드와의 관계를 설명한다.

## 구현

- 발견 시 각 사건에 유물 후보 3개를 예약한다. 각 사건은 범용 유물(수집 회복 또는 피격 반격)을 하나 포함하고, 가능한 경우 현재 무기와 연결되는 후보를 포함한다.
- 두 사건의 후보는 겹치지 않는다. 고른 유물과 관계없이 각 사건의 제안은 고정되어 미리보기·완료 시 다시 뽑히지 않는다. 수집 회복과 피격 반격을 첫 사건에서 모두 예약하지 않으므로 두 사건에 범용 선택지가 남는다.
- 도전하지 않은 사건의 후보도 해당 판에서 예약된다. 다른 사건에서 다시 나타나지는 않는다. 두 사건 전체에서 여섯 유물의 다른 제안을 볼 수 있다.
- 전투의 보상 후보 버튼은 전투를 정지하고 조건과 후보를 보여준다. 숫자키로 유물을 얻거나 저주를 수락할 수 없으며 돌아가기/Esc/P로 같은 상태에서 재개한다.
- 저주 상자 수락 화면에도 실제 후보를 보여준다. 진행 중인 사건에서 미리보기를 열어도 저주/봉인 시간이 멈추며, 수락·취소·보상 지급 상태를 바꾸지 않는다.
- 유물 카드에 현재 무기 연결, 무기 필요, 연소 전문화 강화, 수집 회복, 피격 후 반격을 표시한다. 아직 무기가 없어 효과가 적용되지 않는 유물도 선택 가능하며 조건을 명시한다.
- 보상 계획은 전용 시드 난수를 쓴다. 미리보기나 후보 생성이 적 생성·성장 선택의 난수를 소비하지 않는다.

## 검증

40시드 × 3캐릭터에서 두 사건 후보의 개수, 서로 다른 예약, 범용 선택지, 실제 완료 후 동일 후보를 확인한다. 미리보기 중 시간·체력·사건 상태·유물 보유가 바뀌지 않는지와 숫자키/중복 열기/종료 상태를 확인한다. 실제 연소·정예 피해·둔화·이동 중 쿨다운·수집 회복·반격 검사는 기존 행동 검사로 유지한다.

일반 입력 진단 6경로 × 3시드에서 14판 군주 격파, 4판 시간 생존이었다. 모든 경로가 진화와 최종 구간에 도달했다. 자동 입력의 유물 우선순위가 고정되어 있으므로 이 결과는 사람의 선호·승률·재플레이 의사를 증명하지 않는다. [전체 진단](./choices-balance-2026-10-06.jsonl).

브라우저에서는 보상 미리보기, 실제 제단/상자 완료 후보 일치, 키보드와 복귀, 1280px/320px/740px 화면을 확인한다. 검증 결과와 배포 상태는 완료 후 아래에 추가한다.

## 후속

결과에서 이번 판에 새로 발견한 선택과 다음에 시험할 빌드를 연결한다. 현재 조사와 구현은 위험 대비 보상의 가독성을 개선하며, 자발적 재도전 증가의 확인은 실제 플레이 피드백으로 남는다.

## 로컬 결과

단위 검사 91개와 브라우저 시나리오 73개가 통과했다. Pages용 빌드와 프로덕션 시작·정지·자산·QA 전역 제거 검사도 통과했다. 시각 검수에서 데스크톱의 세 후보가 좁게 보인 점을 수정해 미리보기와 상자 수락 화면에 일반 패널 폭을 사용했다. 영향받는 8개 제단·상자·세 화면 크기의 검사를 다시 실행한다.

최종 패널 수정 후 영향받는 8개 시나리오도 통과했다. [검사 요약](./choices-local-qa-2026-10-06.json), [데스크톱 화면](./images/reward-preview-1280.png), [320px 화면](./images/reward-preview-320.png)을 기록했다. 짧은 화면에서는 세로 스크롤로 후보와 복귀 버튼을 모두 볼 수 있다.

인앱 브라우저의 일반 실행에서도 검을 강화하고 45초 이후 발견한 제단의 실제 보상 미리보기를 열어 현재 검 연결/미보유 불씨 조건/수집 회복이 함께 표시되는 것을 확인했다. 후보 미리보기·복귀는 자동 시나리오와 일반 UI 양쪽에서 검수했다. main 전달 후 자동 Pages 배포를 확인할 예정이며, 전체 개발 목표는 다음 빌드/결과 연결과 최종 출시 대조까지 계속 진행한다.
